# Components

Organized by feature under `src/lib/components/` (`chrome/`, `composition/`, `capture/`, `clipping/`, `time/`, `scale/`, `settings/`, `help/`, `keyboard/`, `dropzone/`, `loading/`, `sounding/`). Primitive UI lives under `src/lib/components/ui/` and is managed by `shadcn-svelte` — regenerate with `npm run upgrade:ui` (uses `components.json`). Aliases: `$lib/components`, `$lib/components/ui`, `$lib/utils`.

**Primitives `ui/` personnalisées (à réappliquer après `npm run upgrade:ui`)** — le verre dépoli du chrome a modifié certaines primitives au-delà de la génération shadcn :

- `ui/select/select-content.svelte` — fond verre translucide (`bg-glass/85 backdrop-blur-xl`, `border-none`, `rounded-lg`) au lieu de `bg-popover ... border shadow-md`, pour que les dropdowns `Select` (unités, run…) s'accordent au reste du chrome verre. `text-popover-foreground` est conservé (adaptatif clair/sombre).
- `ui/switch/switch.svelte` — état coché en **bleu ciel** (`data-[state=checked]:bg-sky-500`, pouce blanc `dark:data-[state=checked]:bg-white`) au lieu de `bg-primary` (qui, en dark, vaut un quasi-blanc → switch peu lisible). L'accent « sky » est la teinte d'état actif du panneau Calques & réglages, fidèle au sujet (carte du ciel) ; icône + libellé d'un calque actif sont teintés `text-sky-300` (cf. `chrome/layer-toggle.svelte` et les composants `settings/`).

Si d'autres primitives `ui/` sont retouchées pour le style verre, les lister ici.

**Popovers `Command` scrollables (mobile)** — tout `Popover.Content` qui contient une liste `Command` scrollable doit poser `tabindex={0}` + `onOpenAutoFocus={(e) => e.preventDefault()}` (puis, optionnellement, focus de l'item actif via `[data-value="…"]`). Sans ça, le popover autofocuse l'`Command.Input` à l'ouverture → le clavier virtuel monte sur mobile et capte le geste de scroll de la liste (liste « bloquée » au doigt). Pattern en place sur le sélecteur de modèle (`chrome/model-selector.svelte`) — les sélecteurs de variable et de niveau sont désormais des listes simples (lignes + puces de niveau) dans `chrome/layer-list.svelte`, sans Popover ni Command. La recherche reste accessible : taper sur le champ ouvre le clavier volontairement.

Map controls are plain Svelte components rendered in the app chrome, not MapLibre `IControl`s (les contrôles **natifs** MapLibre — zoom, boussole, géoloc, globe, 3D — sont ancrés en **bas-droite**, remontés au-dessus de la timeline via `bottomChromeHeight` dans `+page.svelte`). Chrome (refonte header + sidebar, spec `docs/superpowers/specs/2026-07-01-refonte-interface-precip-design.md` ; **coquille tableau de bord** — chrome bleu-nuit, bande de contexte, actions flottantes, en-tête = modèle/run/validité — spec `docs/superpowers/specs/2026-07-02-refonte-interface-dashboard-design.md`) :

- `chrome/header.svelte` — barre fine pleine largeur (44 px, `h-11`) : logo Infoclimat, onglet « Carte » en pilule (emplacement des futures pages), **fil contextuel `Modèle · Run · Validité`** (chiffres `tabular-nums`) + badge « Run en cours » quand le run affiché est encore en génération (`inProgressReferenceTime`, calqué sur `time-selector.svelte`), bouton « Avancé » qui toggle `advancedOpen`. La **variable** ne vit plus dans le header (déplacée dans `context-strip`).
- `chrome/sidebar.svelte` (desktop) — sous le header (`top-11`) : **rail d'onglets** vertical toujours visible (48 px, `role=tablist` vertical, flèches haut/bas, barre sky sur l'onglet actif, pastille = nombre de superpositions sur « Compositions », Aide en pied) + **panneau** de l'onglet actif (296 px, **272 px sous 1440 px** de large ; en-tête titre + sous-titre + bouton replier). **Petits écrans** (14″) : sous 820 px de haut, sous-titres décoratifs (en-tête, groupes de `display-section`/`composition-panel`, libellé « Modèle » de la carte modèle) masqués via `[@media(max-height:820px)]:hidden`. Clic sur l'onglet affiché → replie (seul le rail reste) ; sur un autre → l'ouvre. États persistés `sidebarCollapsed` + `sidebarTab` ; largeur publiée dans `sidebarWidth` pour décaler timeline (`time-selector.svelte`) et légende (`scale.svelte`).
- `chrome/sidebar-tabs.ts` — définition des 4 onglets (`layers` « Données », `compositions`, `map` « Carte », `cyclones` « Cyclones IA » : clé, libellé, sous-titre, icône), partagée sidebar/mobile.
- `chrome/panel-content.svelte` — contenu d'un onglet, **source unique** desktop/mobile : Données = `model-selector` (variante `card`) + mentions du modèle IA Weather AI quand il est sélectionné (`weather-ai/weather-ai-model-notice.svelte`) + `layer-list` ; Compositions = `composition-panel` ; Carte = `display-section` ; Cyclones IA = `weather-ai/weather-ai-panel`.
- `chrome/model-selector.svelte` — prop `variant` : `pill` (bouton compact, défaut) ou `card` (pleine largeur sur deux lignes — libellé du modèle jamais tronqué —, popover aligné à gauche).
- `chrome/layer-list.svelte` — **recherche** de variable en tête (`#variable-search`, insensible aux accents, libellé FR + identifiant technique ; résultats à plat avec icône de famille, Entrée = 1er résultat, Échap = vider ; raccourci global `/` dans `keyboard-handler.svelte`, qui ouvre l'onglet Données — `d` aussi, le sélecteur de modèle n'étant monté que dans cet onglet), puis accordéon des familles (compteur de variables) ; niveaux de la variable active en **puces** (`role=radio`, libellé court `shortLevelLabel` « 850 hPa »), séparées « Hauteur » / « Pression » quand les deux existent. **Unité d'affichage alignée à droite** de chaque ligne variable (`tabular-nums`), calculée par ligne via `getColorScale`→`getDisplayUnit` (miroir de `scale.svelte`/`context-strip.svelte` ; omise quand vide). Logique pure dans `src/lib/layer-list.ts` (testée : `src/lib/tests/layer-list.test.ts`).
- `chrome/context-strip.svelte` — bande de contexte fine (`h-[26px]`, `bg-glass/70 glass-blur`) sous le header, au-dessus de la carte, décalée à droite par `sidebarWidth` (desktop). Affiche `Variable (unité)` — libellé via `translateVariableLabel($selectedVariable.label)`, unité d'affichage réelle en miroir inline de `scale.svelte` (`mode.current` étant une rune, pas de store partagé possible sans cycle). Masquée si aucune variable.
- `chrome/map-actions.svelte` — cluster flottant **desktop-only** en haut-droite de la carte (`fixed top-[82px] right-3 z-40` = header 44 + context-strip 26 + 12) : **copier le lien** (`location.href`, retour ✓ 1,5 s) et **plein écran** (`requestFullscreen`/`exitFullscreen`, listener `fullscreenchange` nettoyé). Pas de bouton capture/télécharger (la capture reste au header desktop / FAB mobile — anti-doublon).
- `chrome/display-section.svelte` — onglet « Carte » en groupes titrés : **Calque météo** (isocontours, flèches, valeurs aux points, opacité), **Fond de carte** (départements, villes & pays, relief ombré, fond sombre), **Interaction** (infobulle). L'édition d'échelle reste dans la légende `scale/`. (`style-section.svelte` n'existe plus.)
- `chrome/mobile-dock.svelte` (mobile) — FAB capture + poignée « Données & carte » au-dessus de la timeline ouvrant un bottom-sheet avec les **mêmes 4 onglets** (contrôle segmenté, `SIDEBAR_TABS` + `panel-content`, onglet partagé via `sidebarTab`).
- `chrome/advanced-panel.svelte` — panneau « Avancé » (drawer desktop ancré sous le header / Sheet mobile) : calque secondaire, unités, performance (tuiles + cache), réglages avancés (points de grille, sondage, réinitialisation), outils (capture, découpage, aide). N'a plus de bouton déclencheur propre.
- `chrome/app-chrome.svelte` — compose header (toujours) + sidebar (desktop) ou bottom-sheet (mobile) + advanced-panel + `context-strip` + `weather-ai-map-card` ; `map-actions` monté desktop-only.

`weather-ai/` — couches expérimentales Weather AI (voir `.claude/rules/architecture.md`, § _Couches Weather AI_) : `weather-ai-panel.svelte` (onglet « Cyclones IA » : avertissement permanent, **superpositions** issues du catalogue — « Cyclones, trajectoires et zones à surveiller », cônes seulement si le flag les propose ; pas de champ continu ni de curseur propre, l'échéance suit la frise —, bloc « Source des superpositions » : run Weather AI + échéance réellement affichée + « entre deux échéances » / « hors horizon », légendes vent km/h / zones à surveiller / cônes, liste des cyclones suivis, note « pression et probabilité : à venir comme modèle du sélecteur », détails run/sources/licence ; son montage suffit à lire le catalogue), `weather-ai-map-card.svelte` (carte flottante `fixed top-[82px]` décalée de `sidebarWidth`, visible dès qu'une couche est active même panneau replié : badge, avertissement, « Échéance Weather AI `+N h · JJ/MM HH:MM UTC` » et « run Weather AI `run_id` » de l'état **réellement affiché**, relation à la frise (« entre deux échéances » seulement si l'échéance demandée est **effectivement affichée** — `betweenShown` —, sinon « échéance demandée … en chargement / non affichée » via `summary.requested`, run demandé nommé s'il diffère ; hors horizon avec l'horizon du run). Run et initialisation affichés viennent **toujours** de `weatherAiDisplayed` (`summary.shown`), jamais de `weatherAiRun` (qui peut être un run en préparation), run Weather AI distinct du fond dans le « i » (`weatherAiDisplayed` via `cardSummary`, `weather-ai/displayed.ts` — pas la sélection, qui peut être en chargement ou en échec), « Chargement de +N h… » tant que la sélection n'est pas affichée, **erreur toujours visible** (bloc `role=alert` indépendant de la présence d'un run), mention des cônes, « i » → mentions ; plus de pas à pas : l'échéance suit la frise ; porte aussi l'`$effect` qui appelle `syncWeatherAiLayers()`), `weather-ai-mentions.svelte` (attribution/licence reçues + mentions imposées par les sources).

`composition/` — panneau « Compositions » (portage des « Combined charts » + « Current chart » d'open-meteo/maps, même style verre que `layer-list`) : `composition-panel.svelte` assemble, **construction d'abord** (on doit pouvoir partir de zéro sans passer par un modèle), « Votre composition » (`composition-editor.svelte`) puis « Partir d'un modèle » (`preset-list.svelte`) (compositions toutes faites groupées + « Mes compositions », groupes repliables persistés `composition-groups-open`, indisponibles grisés en bas de groupe) ; `composition-editor.svelte` (fond **modifiable sur place** — bouton « Changer » → picker en mode `base` → `setBaseVariable`, superpositions conservées —, état vide explicite, puis superpositions : bascules Aplat/Isolignes/Flèches, niveau de la superposition — `<select>` natif alimenté par `overlayLevelOptions`, portage du `source-level-select.svelte` d'upstream sans Popover/Command, cf. règle mobile ci-dessus ; un niveau déjà superposé est désactivé —, intervalle d'isolignes — flèches haut/bas via `stepInterval`, vide = paliers —, retrait, enregistrement et « Tout retirer » affichés seulement s'il y a au moins une superposition), qui ouvre `overlay-variable-picker.svelte` (prop `mode` : `overlay` = `addOverlay`, `base` = remplace le fond ; recherche à plat niveaux inclus via `searchVariables`, Entrée = 1er résultat libre, focus auto desktop seulement ; sinon familles comme « Données »). Les composants n'appellent que les actions de `composition-actions.ts` ; logique pure dans `src/lib/composition-list.ts` (testée : `tests/composition-panel.test.ts`).

`scale/scale.svelte` — légende : hauteur des paliers **adaptée à la fenêtre** (`legendBlockHeight` : 20 px max — 10 px mobile ≥ 20 paliers —, plancher 8 px, place = `innerHeight` − header/bande − ancrage bas − ~70 px d'unité/boutons) et libellés espacés (`legendLabelStep`, un sur N quand les paliers font < 14 px) ; helpers purs dans `src/lib/color-scales/legend.ts` (testés : `tests/legend.test.ts`). Avant : 35 paliers × 20 px débordaient sous le header sur un 14″.

`top-bar.svelte` et `variable-tabs.svelte` n'existent plus. Hillshade is initialized from prefs via `initHillshadeFromPrefs()` (`src/lib/hillshade.ts`), not a button.

`sounding/` — panel tabulé (Skew-T / hodographe / indices) avec tracés SVG sur mesure, ouvert depuis le popup de valeur au clic sur la carte (`src/lib/popup.ts`). Voir `src/lib/sounding/` pour la logique pure associée.

`point-workspace/` — « espace point » : tiroir bas ouvert depuis le bouton « Meteogram » du popup (`popup.ts`, gaté par `hasMeteogram(domaine)` — voir `.claude/rules/architecture.md`), pensé comme une **coquille extensible** dont le meteogram est le premier module (v1). **Raccourci clic droit** : un `contextmenu` sur la carte (`popup.ts → addPopup`) épingle directement la bulle-viseur en mode `drag` (1 geste au lieu de 3 clics gauche) → le bouton « Météogramme » est cliquable immédiatement. La bulle **reste le viseur compact** (valeur/unité/vent) — pas d'enrichissement coords/altitude (jugé chargé, et `queryTerrainElevation` ne renvoie rien sans DEM chargé). Le flux clic gauche (suivi → épinglage) est inchangé. **L'altitude du point** est affichée dans l'**en-tête du tiroir** (`point-drawer.svelte`), depuis le champ `elevation` de l'API forecast (fiable, indépendant du terrain 3D).

- `point-drawer.svelte` — le tiroir lui-même : redimensionnable (poignée `pointerdown`/`pointerup` en haut, plus flèches haut/bas au clavier sur un `role="separator"`), en-tête `<coordonnées> · <Modèle> · dernier run · <altitude> m` (altitude via la prop bindable `elevation` du meteogram, alimentée par `elevation` de l'API), bouton « Exporter PNG » (appelle `exportPng(filename)` du composant meteogram via `bind:this`) et bouton fermer. Pose un `maplibregl.Marker` ambre dédié sur la carte pour matérialiser le point choisi, distinct du popup de valeur (créé/déplacé/retiré au fil de `$pointWorkspace`). **Layout** : décalé à gauche de `sidebarWidth` (`left`, comme la timeline/légende — sinon la sidebar masque le début du tiroir) ; publie sa hauteur dans le store `pointDrawerHeight` (0 quand fermé) pour que la légende (`scale.svelte`, bottom desktop) et les contrôles MapLibre bas-droite (`+page.svelte`) se placent **au-dessus** du tiroir ouvert (`max(bottomChromeHeight, pointDrawerHeight)`) au lieu d'être recouverts.
- `meteogram/meteogram.svelte` — orchestration (fetch mémoïsé `SvelteMap`, refetch sur point/modèle jamais sur le scrub, états chargement/429/réseau/vide, conversion d'unités) + rendu **Highcharts** (graphe unique façon yr.no) : import dynamique de `highcharts` + modules `windbarb`/`exporting`/`offline-exporting` au premier affichage, builder pur `src/lib/meteogram/meteogram-chart.ts` (4 axes Y : T°+point de rosée / précip / pression / humidité masquée par défaut ; windbarbs 1/2 ; légende ; tooltip partagé ; zoom X + `scrollablePlotArea` ; axe temps fusionné heures+date), icônes météo (`weather_code`+`is_day` → `src/lib/meteogram/weather-symbols.ts` → SVG bundlés `static/weather-symbols/`, MIT) redessinées à chaque `render`. Playhead = `plotLine` X repositionnée au scrub (pas de re-render) ; clic chart/point → `nearestValidTime` + `goToValidTime`. Expose `exportPng(filename)` (délègue à `src/lib/meteogram/export-image.ts → renderMeteogramExport`), appelée par `point-drawer.svelte` via `bind:this`. Licence Highcharts : CC BY-NC (non-profit), note au README.

  **Export PNG « carte de visite » (`export-image.ts`).** L'export ajoute un pied de page (logo Infoclimat en data URI `infoclimat-logo.ts` à gauche, `Modèle · lat,lon · généré le … UTC` à droite — `buildExportContextLine`) sous le graphe, sur fond opaque sombre, pour un partage social/forum propre. **Pas** via Highcharts (`exportChartLocal`/events du chart) : en **12.6**, le chart d'export recréé par `getSVGForExport` **ne rejoue ni `load` ni `render`** — un pied dessiné via ces events n'apparaît pas, et **les pictos météo (dessinés au `render`) sont eux aussi absents de tout export** (défaut amont, pas propre au watermark). On reprend donc la main en **composition canvas 2D** : `getSVGForExport` (fond sombre forcé) → `inlineSvgImageHrefs` (remplace les `href` externes des pictos par des data URIs — un SVG rasterisé via `<img>` ne charge pas ses sous-ressources externes) → rasterisation → pied peint au canvas → `scale: 2` → téléchargement. Fonctions pures testées (`tests/meteogram-export.test.ts`) ; la composition canvas (DOM) est vérifiée en headless.

Logique pure associée sous `src/lib/meteogram/` (api, model-map, snap, types, weather-symbols, meteogram-chart — testée), voir `.claude/rules/architecture.md`.
